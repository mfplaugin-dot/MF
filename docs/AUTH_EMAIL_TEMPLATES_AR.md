# قوالب بريد الحساب — Staging

هذه نصوص جاهزة للمراجعة؛ لم تُدخل في لوحة Supabase ولم تُرسل لأن SMTP غير مهيأ. إبقاء تأكيد البريد مفعّلًا شرط، وليس تعطيله حلًا لغياب SMTP.

## تأكيد عنوان البريد

**الموضوع:** أكّد بريدك الإلكتروني لحساب MF Plugin

مرحبًا،

استُخدم هذا البريد لإنشاء حساب MF Plugin. لتأكيد العنوان ومتابعة إنشاء الحساب، استخدم الرابط:

`{{ .ConfirmationURL }}`

إذا لم تطلب إنشاء الحساب، فتجاهل هذه الرسالة. لا تشارك رابط التأكيد مع أي شخص.

## إعدادات العودة المقترحة للاختبار

- يمرر الموقع `VITE_AUTH_REDIRECT_URL` إلى تأكيد الحساب وطلب الاستعادة.
- قيمة التطوير المحلية في `.env.example` هي `http://localhost:5173`.
- أضف فقط روابط Staging الفعلية المعتمدة إلى قائمة Redirect URLs في Auth؛ لا تضف wildcard واسعًا ولا تستخدم نطاق الموقع الحي قبل نشر نسخة Staging ومراجعة مسار العودة.
- معالج الموقع يتعامل مع حدث `PASSWORD_RECOVERY` ويعرض نموذج تعيين كلمة مرور جديدة. يلزم اختبار الرابط فعليًا بعد تهيئة SMTP.

## بيانات SMTP المطلوبة من المالك

لا تتوفر حاليًا بيانات يمكن التحقق منها. يلزم الحصول عليها من مزود البريد المختار وإدخالها مباشرة في لوحة Staging:

- اسم خادم SMTP والمنفذ.
- اسم المستخدم وكلمة المرور/بيانات اعتماد التطبيق.
- عنوان المرسل واسم العرض.
- تأكيد ملكية النطاق وإعداد سجلات SPF وDKIM وDMARC لدى المزوّد عند انطباقها.
- حدود الإرسال ومعدلات الاستعادة المسموح بها.
- رابط HTTPS النهائي لـ Site URL وRedirect URLs لنسخة Staging.

لا تضع كلمة مرور SMTP في `VITE_*` أو Git أو المحادثة. لا تُوقف تأكيد البريد، ولا تعتبر اختبار القوالب ناجحًا قبل إرسال رسالة فعلية واستلامها والتحقق من رابط العودة.
